# 既知の限界

実データで確認できている制約と、意識的に対応していない項目です。
発生率は都道府県で層化した564件のサンプルでの実測です。
地割だけは母数が異なるため、その節に明記します。

## ライセンス上、意図的に出力しないもの

地番方式の住所については番地を出力しません。
層化サンプルでは564件中243件（43.1%）が該当し、`_備考` に `地番方式のため対象外` が入ります。
町字までの階層は ABR 由来なので出力します。

地番由来の座標も出力しません。
`point.level === 8` で `metadata.rsdt` の裏付けがないものを地番由来と判断します。
ライセンス上の確認が取れていないための保守的な措置で、対象外だと確認できれば緩めてよい判断です。

これらは欠陥ではなく仕様です。
詳細は [README のライセンス上の制約](../README.md#ライセンス上の制約) にあります。

### 判定は地番データの存在に依存します

この分類は NJA が `metadata.chiban` を返すことに依存しています。
そのため住所データを手元に構築する場合も、地番データを含める必要があります。

地番データが無いと `metadata.chiban` が返らず、地番が残余として `note` タグに載ります。
「地番方式のため対象外」だった住所が「住居表示未実施の町字」に移り、下の [`note` に地番が残る](#note-に地番が残る) と同じ状態になります。
層化サンプルでは43.1%が該当するため、影響は小さくありません。

省こうとした場合に何が起きるかの実測は [local-mirror.md](local-mirror.md#地番データは省けません) にあります。

## `note` に地番が残る

住居表示未実施の町字では、NJA が番地を解決できず残余が `note` タグに残ります。
該当カテゴリ72件のうち49件（68%、全体の8.7%）で `note` が数字で始まります。

```
福島県白河市六反山１０－３６
  → addr:neighbourhood=六反山, note="10-36"
```

住居表示未実施の区域は地番で運用されているので、この数字は実質的に地番です。
それでもそのまま出力しています。
値の出自が利用者の入力文字列であって、地番データベースの参照結果ではないためです。
ライセンス制約は「地番データを参照した結果を出さない」ことであり、利用者が自分で持っている文字列をそのまま返すことは対象外と判断しました。

OSM にアップロードする前に `note` を確認するか、数字で始まる `note` を落とす処理を呼び出し側で入れてください。

## `地割` が `addr:neighbourhood` に入る

OSM の公式サンプルは「第○地割は place に入れるのは不適」としています。
しかし NJA が `koaza` または `oaza_cho` として返すため、現状は `addr:neighbourhood` または `addr:quarter` に入ります。
厚労省の医療機関データ206,043件のうち258件（0.125%）で発生します。
`第○地割` は岩手県にのみ存在するため、岩手県の住所1,994件を通せば確定します（県内では12.9%）。
入力文字列に「地割」を含むのは218件で、残りは NJA が住所データ側から補って出力に入れたものです。

表記も揺れます。
町字マスタで地割を含む6,706レコードの内訳は、全角算用数字が6,671件、漢数字が35件です。
`第` を伴うものが4,548件、伴わないものが2,158件あります。

方針の判断材料は [chiwari.md](chiwari.md) にまとめてあります。

## 丁目の告示表記は大字側からのみ復元できる

`chome` は ABR データ自体が常に漢数字で、告示の表記が上流に存在しません。
一方 `oaza_cho_k`（カナ）は告示の数字表記を保持しているので、大字のカナに算用数字が含まれる場合は大字と丁目の両方を算用数字にします。

これで大字に数字を含む地域（北海道の条丁目など）は OSM 公式サンプルと一致します。
大字に数字を含まない地域は手がかりがなく、漢数字になります。

| 住所 | 出力 | 公式サンプルの期待値 |
| --- | --- | --- |
| 流山市江戸川台西4丁目 | `江戸川台西四丁目` | `江戸川台西4丁目` |
| 堺市堺区市之町西1丁 | `市之町西一丁` | `市之町西1丁` |
| 横浜市鶴見区朝日町1丁目 | `朝日町一丁目` | `朝日町1丁目` |
| 横浜市旭区二俣川1丁目 | `二俣川一丁目` | `二俣川1丁目` |

自治体別の告示表記の一覧を持てば解決しますが、調査と維持のコストがかかるため実装していません。

## NJA が町字を特定できないケース

NJA は市区町村までしか特定できなかった場合、`machiAza` を省略せず `{ machiaza_id: '0000000' }` のプレースホルダを返します。
この場合 `addr:neighbourhood` が出ず、`_備考` に `町字を特定できず` が入ります。
564件では0.7%程度です。

登記のみで使われる通称地名も特定できません。
長野市大字鶴賀権堂町の場合、NJA は `oaza_cho=大字鶴賀` のみを返し、権堂町は残余に落ちます。

## 実装しないと決めたもの

| 項目 | 理由 |
| --- | --- |
| 地番方式の番地変換 | ライセンス |
| `addr:full` | 京都の通り名を含む住所かどうかを NJA の出力から判定できない。NJA が通り名を吸収して残余が空になる |
| `addr:housename` / `addr:room` / `addr:floor` の自動パース | 建物名と部屋番号と支号を判別できない。残余は `note` に回す |
| `無番地` | 地番方式の概念で、住居表示のみを対象とする以上発生しない |
| カナ・ローマ字・自治体コードのタグ化 | OSM に権威のあるタグ名がない。`extra` で返し、使い道は呼び出し側に委ねる |
| 自治体別の丁目表記の例外リスト | 上記のとおり調査と維持のコスト |
