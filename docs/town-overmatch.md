# 町字の過剰一致の調査記録

入力が指している町字とは別の町字が出る不具合の調査記録です。
発端は `docs/chiwari.md` に記録した1件です。

```
入力     岩手県上閉伊郡大槌町大槌１５地割９５ー１５
出力     neighbourhood=大町   note="槌15地割95-15"
```

**2026-08-26: 一部に対応しました。**
入力から1文字も取らずに決まった町字（7自治体）は落とすようにしました
（`src/machiAza.ts` の `dropFabricatedMachiAza`）。
残りはマスタ照会が必要で本ツールでは判定できないため、上流への報告に回します。

## 原因

3つの別々の問題が重なっています。
1と2で正しい町字の照合が外れ、3がその結果を「町字を特定できず」から
「誤った町字」に変えます。

### 1. 照合の網羅が足りない

正しい町字がマスタにあるのに、書き方の揺れで当たりません。
実データで見た限り2つの形があります。

**地割のパターンが `第` を必須にする。**
`大槌第１５地割` はマスタに存在します（`machiaza_id=0017134`）。
しかしパターンは数字部分だけを選択肢にして `第` を literal に残します。

```
大槌第(１５|15)((丁|町)目?|…|地割|号|[-－…])
```

入力 `大槌１５地割` はこれに一致しません。
`第` を伴わない町字がマスタに2,158件あるので（[chiwari.md](chiwari.md)）、
入力側で `第` が省かれるのは自然な書き方です。

**素の町字レコードが無く、入力が丁目を書いていない。**
こちらのほうが件数が多いです。

```
入力     神奈川県横浜市鶴見区鶴見中央
出力     neighbourhood=鶴見町   note="中央"
```

鶴見区のマスタには `鶴見中央一丁目`〜`五丁目` があり、素の `鶴見中央` はありません。
NJA のパターンは町字名の**全体**に対して作られるので、丁目まで含むパターンは
丁目を書いていない入力に一致しません。
丁目の数字を補う予備パターン（`^鶴見中央(1|一)`）は数字を要求するので、
入力がそこで終わっていると一致しません。

数字を付ければ通ります。

| 入力 | 結果 |
| --- | --- |
| `横浜市鶴見区鶴見中央` | `鶴見町`（誤り） |
| `横浜市鶴見区鶴見中央1-1` | `鶴見中央一丁目`（正しい） |

### 2. 候補を「町字名の長さ」で選ぶ

網羅の問題ではありません。
**データは揃っていて、入力もマスタどおりに書かれていて、それでも間違えます。**

白石市には `字沢端` と `沢端町` が両方実在し、どちらも3文字です。

```
入力     宮城県白石市沢端町1-37
出力     neighbourhood=字沢端   note="町1-37"
```

パターンは町字名の文字数の降順で試され、最初に当たったものを採ります。
`字沢端` のパターン `(大?字)?沢端` は入力の先頭2文字に当たり、
`沢端町` は3文字を丸ごと一致させるのに、名前の長さが同じなので順番で負けます。

**並び替えのキーが「実際に一致した長さ」ではありません。**
そのため丸ごと一致が部分一致に負けます。

### 3. 外れたときに未特定を返さない

1と2で照合が外れたあと、NJA は「町字を特定できず」を返しません。
当たったパターンの中でいちばん町字名が長いものを返します。
当たるものが1つも無いときだけ未特定になります。

```
横浜市鶴見区鶴見中央
  鶴見中央一丁目  外れる（丁目が無い）
  鶴見一丁目      外れる
  鶴見町          外れる（町 が無い）
  鶴見            当たる  ← これを返す（鶴見町 の別名）
```

**欠測が誤データに変わります。**
OSM に入れる立場では、この差が決定的です。
欠測は後から埋められますが、誤った `addr:neighbourhood` は、
それが誤りだと分からないまま入ります。

### 短く一致するパターンを増やす3つの処理

3が拾う「短い部分一致」は、素の町字名からも来ますが、
NJA が `getTownRegexPatterns`（`src/lib/cacheRegexes.ts`）で生成する略記からも来ます。
実データでは略記由来が3分の2、素の町字名が3分の1でした。

**「町」を落とした別名。**

```js
const townAbbr = originalTown.replace(/(?!^町)町/g, '')
```

`大町通` のような住所で `町` が省略される書き方に対応するための処理です。
しかし2文字の町字名では**1文字のパターン**になります。`大町` は `大` に一致します。

**「大字」「字」を任意にする。**

```js
.replace(/大?字/g, '(大?字)?')
```

`字浜` は `(大?字)?浜` になり、`浜` の1文字に一致します。
こちらは表記の揺れとして正当な処理です。
`大字結城` と `結城` は同じ場所を指します。

**両方が重なると空文字列に一致します。**
`字町` の別名は1つめで `字` になり、2つめでその `字` が任意になって `(大?字)?` に
なります。この自治体では**入力が何であれ町字が決まります**。

これらは原因ではなく増幅器です。
同じ「照合できない」入力でも、その自治体に短い別名が無ければ正しく未特定になります。

| 入力 | 結果 |
| --- | --- |
| `大槌町大槌第１５地割９５ー１５` | `大槌第１５地割` level=8（正しい） |
| `大槌町大槌１５地割９５ー１５` | `大町` other=`槌15地割95-15`（誤り） |
| `大槌町小鎚１５地割1-2` | 町字未特定 level=2（正しい挙動） |

`小鎚` は `小町` が存在しないため1文字の別名が無く、誤った町字が出ません。

### 候補生成の妥当性

候補にしなかった頭文字5,894件を対照として問い合わせ、
1文字で町字が決まったものが5件ありました。

**A で説明できないものは0件**でした。
候補生成の取りこぼしは検出されていません。

## 上流で直すなら

原因の1（網羅）は、データにも入力にも揺れが残る以上、完全には潰せません。
効くのは2と3です。

**2: 候補は「一致した長さ」で選ぶ。**
いまの並び替えのキーは町字名の長さです。
これを実際に一致した長さに変えれば、`沢端町` が `字沢端` に勝ちます。
入力どおりに書かれた住所が別の町字になる形は、これで消えます。

**3: 短い部分一致しか残らなかったときは町字を返さない。**
入力の語の途中で切れる一致しか無いなら、「町字を特定できず」を返す。
これを入れると、いま誤っている行の多くが未特定になります。
**件数は減りませんが、誤データが欠測に変わります。**
OSM に投入する立場では、これがいちばん効きます。

短く一致するパターンを増やす3つの処理（`町` の省略、`大?字` の任意化、
その合成による空文字列一致）を絞る手もありますが、実測すると効きません。

`町` を落とした別名で一致した154行を、別名の長さで分けました。

| 別名の長さ | 行数 | 例 |
| --- | --- | --- |
| 1文字 | 53 | `大町` → `大` |
| 2文字 | 77 | `鶴見町` → `鶴見` / `矢田町` → `矢田` |
| 3文字 | 21 | `宮野木町` → `宮野木` |
| 4文字 | 3 | `肥田町浅野` → `肥田浅野` |

「別名が1文字なら登録しない」で消えるのは**401件中53件（13%）**です。
いちばん多い2文字の別名は残ります。
長さで切る限り、どこで切っても正当な省略（`○○町` を `○○` と書く形）を巻き込みます。

だから本筋は2と3です。
2は入力どおりに書かれた住所が別の町字になる形を消し、
3は残りを誤データではなく欠測に変えます。

なお2と3で失われる正当な解決がどれだけあるかは測っていません。
1文字の別名で正しく解決している住所（`大槌町大1-2` が `大町` になる形）が
実データにどれだけあるかを数える必要があります。
