# 地割の調査記録

`第○地割` を `addr:neighbourhood` に入れている現状について実測した記録です。
この文書は判断材料であって、決定した仕様ではありません。

**決めるのはこのリポジトリではありません（2026-09-01）。**
地割を `place` タグに入れるかどうかは OSM のタグ付け規約そのものなので、
OSM コミュニティの議論を経る必要があります。
以前この文書は「方針未決」とだけ書いており、誰が決めるのかを曖昧にしていました。
下の選択肢A/B/Cは、その議論に持ち込むための整理です。

## 何が問題か

OSM 公式のタグ付け例は「第○地割は place に入れるのは不適」としています。
しかし NJA が `koaza` または `oaza_cho` として返すため、現状は `addr:neighbourhood`（大字がある場合は `addr:quarter` と併せて）に入ります。

```
岩手県久慈市夏井町夏井第3地割3-57-1
  現状        quarter=夏井町夏井 / neighbourhood=第3地割 / note=3-57-1
  公式サンプル neighbourhood=夏井町夏井 、3-57-1 は番地側
```

## 判断範囲は place タグだけです

公式サンプルが期待する「番地側に含める」は到達できません。
出力タグに地割が入る258件すべてが `numberSource=none` でした。

| `noNumberReason` | 件数 |
| --- | --- |
| `chiban` | 236 |
| `rsdt-not-implemented` | 21 |
| `machiaza-from-mlit` | 1 |

ライセンス制約により地番方式の番地を出さないため、番地側の期待値は満たせません。
なお258件のうち254件は `addr:quarter` に大字を持ちます。
残り4件は普代村で、大字を持たず地割の後に字名が続く形です。

したがって決めるべきは「地割を place タグに入れるか」の一点です。

## 発生率

| 母数 | 地割 | 率 |
| --- | --- | --- |
| 施設情報5ファイル 206,043件 | 出力タグに地割が入る住所 258件 | **0.125%** |
| 町字マスタ 749,406レコード | 地割のレコード 6,706件 | 0.895% |

岩手県内に限れば1,994件中258件で12.9%です。

入力データは厚労省の医療機関オープンデータ5種（病院・診療所・歯科・助産所・薬局）です。

| ファイル | 全件 | 入力に地割 |
| --- | --- | --- |
| 病院 | 7,715 | 21 |
| 診療所 | 80,155 | 83 |
| 歯科 | 54,637 | 45 |
| 助産所 | 2,138 | 0 |
| 薬局 | 61,398 | 69 |

この列は入力文字列に「地割」を含む行で、合計218件です。
上の表の258件は出力タグに地割が入る行で、母数は同じでも数える対象が違います
（[入力と出力で件数が違います](#入力と出力で件数が違います)）。

### 層化サンプルの0.9%は使えません

都道府県で層化した564件では5件（0.89%）でした。
実データの0.125%との差は7.1倍あります。

内訳は2つです。
岩手県の重みが層化サンプルでは2.13%（12/564）、実データでは0.97%（1,994/206,043）で、2.2倍の差があります。
さらにその12件のうち5件で出力に地割が入り、県内の当たり率が41.7%になっています。
実データの岩手県は12.9%（258/1,994）なので、こちらに3.2倍の偏りがあります。
2.2 × 3.2 が全体の7.1倍にあたります。

**2026-09-01 訂正。** ここは「8.6倍」と書いていました。
層化サンプル側を出力タグの5件で数えながら、実データ側を入力に地割を含む212件
（0.10%）で数えていたためです。
この節が使う発生率は出力側なので、両側とも出力側に揃えました。

### 岩手県だけを測れば足ります

`第?N地割` に一致する6,706レコードは全件が岩手県です。
岩手県以外にも「地割」を含む町字が38件ありますが、`飛地割` や `覚地割` のような通常の字名で、1件も一致しません。
したがって発生率は岩手県の住所1,994件を通すだけで確定します。

### 入力と出力で件数が違います

入力文字列に「地割」を含むのは218件、出力タグに地割が入るのは258件です。
発生率として使うのは後者です。

| 区分 | 件数 |
| --- | --- |
| 入力にも出力にも地割 | 204 |
| 出力にだけ地割 | 54 |
| 入力にだけ地割 | 14 |

出力にだけ出る54件は、NJA が住所データ側から補うためです。

```
入力     岩手県盛岡市永井１２−１０
出力     quarter=永井 / neighbourhood=12地割
```

入力にだけある14件は、NJA が地割を町字として解決できず `note` に残したものです。
このうち1件は誤った町字を出しています。

```
入力     岩手県上閉伊郡大槌町大槌１５地割９５ー１５
出力     neighbourhood=大町   note="槌15地割95-15"
```

`大槌町大槌` に対して `大町` を返しており、`note` は `槌` から始まっています。

**この件は調査済みです。** `大町` の `町` を落とした別名 `大` が `大槌` の頭1文字を
食っています。引き金は地割固有で、`大槌第１５地割` はマスタに存在するのに
パターンが `第` を必須にするため一致しません。
同じ「`第` が無い」入力でも `小鎚１５地割` は正しく未特定になります
（`小町` が存在せず1文字の別名が無いため）。

入力とは別の町字が出る不具合は地割に限らず、医療機関データ206,043件で401件
（0.195%）あります。岩手県はそのうち2行だけです。
原因・発生量・上流への修正案は [town-overmatch.md](town-overmatch.md) にあります。

## 母集団での内訳

町字マスタ749,406レコードを悉皆で走査した結果です。

**2026-09-01 訂正。** 母数を751,304と書いていました。
`out/api/ja` 配下を再帰的に走ると `{都道府県}.json` 47個も拾い、
その `data` は町字ではなく市区町村の索引です。
749,406（`stats.json` の `machiAzaCount`）+ 1,898（同 `lgCount`）= 751,304 でした。
地割の件数は市区町村レコードを拾わないので影響を受けません。

| 形 | 件数 | 地割を剥がした後 |
| --- | --- | --- |
| `koaza=第N地割`（大字あり） | 6,364 | neighbourhood ← 大字 |
| `koaza=第N地割字XX` | 250 | neighbourhood ← 字XX、quarter ← 大字 |
| `oaza_cho=第N地割字XX`（先頭） | 65 | neighbourhood ← 字XX |
| `oaza_cho=XX第N地割`（末尾） | 27 | neighbourhood ← XX |
| 別物（`飛地割` など） | 38 | 触らない |

### place タグが空になるケースは存在しません

方針を決める前に確認が必要だった点です。
「大字が無く、地割の後に何も続かない」住所があると、地割を剥がしたときに `addr:neighbourhood` が空になります。

```
地割が oaza_cho と koaza の両方に入るレコード: 0 件
地割のみのフィールドで、代わりになる名前が他に無いレコード: 0 件
koaza が「第N地割」のみ = 6,364 → うち oaza_cho あり = 6,364（100%）
oaza_cho が「第N地割」のみ = 0
```

標本ではなく母集団での確認なので、これ以上確実な検証はできません。

## 表記の揺れ

`第?N地割` に一致する6,706レコードの内訳です。

| 数字 | 件数 |
| --- | --- |
| 全角算用（`第１地割` `１地割`） | 6,671 |
| 漢数字（`第一地割`） | 35 |
| 半角算用 | 0 |

| `第` | 件数 |
| --- | --- |
| あり | 4,548 |
| なし | 2,158 |

漢数字は必ず `第` を伴います（`第なし × 漢数字` は0件）。
位置は先頭6,679件、末尾27件（末尾は宮古市のみ）。

### 漢数字35件は MLIT 由来の重複レコードです

35件すべて `machiaza_id` が `MLIT:` で始まります。

```
漢数字側  oaza_cho="第十三地割字普代"   machiaza_id=MLIT:034850004000
算用側    oaza_cho="第１３地割字普代"   machiaza_id=0063000
```

ABR の告示表記が2通りあるのではなく、国土交通省データ由来の別レコードが混ざっています。
35件すべてに ABR の算用数字版が併存します（普代村31件、宮古市区界4件）。

**入力の表記でどちらのレコードに当たるかが変わり、ライセンス分類まで変わります。**

| 入力 | neighbourhood | machiaza_id | 分類 |
| --- | --- | --- | --- |
| 普代村第十三地割字普代126番地9 | `第十三地割字普代` | `MLIT:034850004000` | `machiaza-from-mlit` |
| 普代村第１３地割字普代126番地9 | `第13地割字普代` | `0063000` | `chiban` |

MLIT 由来のレコードは明細（`csv_ranges`）を持たないため NJA が地番を解決できず、地番が `note` に載ります。

入力に地割を含む住所（重複除去後212件）の表記は全件が全角算用で、漢数字は0件でした。
現状では発火しませんが、手入力では起こりえます。
MLIT 補完は全国7,617レコード（全町字の1.014%）にわたり、地割固有の問題ではありません。
別途調査が必要です。

## 実装を後押しする材料

**同じ町字が、入力文字列の形によって2つの異なるタグ構造になります。**

```
北上市村崎野第15地割354番3号  → neighbourhood=村崎野 / note=第15地割354-3   (1件)
北上市村崎野第○地割           → quarter=村崎野 / neighbourhood=第N地割      (7件)
```

矢巾町南矢幅も同様です（`neighbourhood=大字南矢幅 / note=7地割453` と `quarter=大字南矢幅 / neighbourhood=第9地割`）。

これは公式サンプルへの準拠とは独立した、出力の自己不整合です。
そして `note` 側に落ちた14件が、たまたまサンプルの期待形と一致しています。

## 選択肢

### A: 現状維持

コストはゼロです。
公式サンプルとの不一致が地割の95%（258/272）で残り、上の自己不整合も残ります。
この文書の実測値で `known-limitations.md` を更新して閉じます。

### B: 地割を place タグから外す

大字を `addr:neighbourhood` に上げ、地割は `note` に回します。
サンプル準拠と自己不整合の解消が同時に達成されます。
`osm-tagging-spec.md` に「残る不一致」として記録している久慈市夏井町夏井の件も、これで期待値と一致します。

#### 実装は1箇所では収まりません（2026-09-01 訂正）

この文書は当初「`machiAzaTags` に分岐を1つ足すだけ」と書いていました。誤りです。
地割は4つの形で現れ、`koaza` だけでなく `oaza_cho` の先頭と末尾にも入ります。

```
久慈市夏井町夏井第3地割   quarter=夏井町夏井 / neighbourhood=第3地割    koaza（6,364件）
普代村第十三地割字普代     neighbourhood=第十三地割字普代               oaza_cho 先頭（65件）
宮古市区界第１地割        neighbourhood=区界第1地割                    oaza_cho 末尾（27件）
```

`oaza_cho` 側の92件を落とすと、`quarter` と `neighbourhood` の決め方そのものを
組み替えることになります。母集団での4形の内訳は上の表にあります。

#### `note` の契約に触ります（2026-09-01 追記）

`note` は「入力の未処理の残余」と定義しています（[api.md](api.md)、
`known-limitations.md` のライセンス論拠もこれに依拠しています）。

しかし地割258件のうち**54件は入力に地割がなく**、NJA がデータ側から補ったものです。
剥がした `12地割` を `note` に入れると、**利用者が書いていない文字列を残余として出す**
ことになります。

```
入力  岩手県盛岡市永井１２−１０
現状  quarter=永井 / neighbourhood=12地割 / note=10
```

ライセンス上の問題はありません（町字は ABR 由来で出力してよい階層です）。
契約の問題です。案Bを採る場合、剥がした地割をどこに置くかは別途決める必要があります。

### C: 大字と地割を連結する

`村崎野第15地割` のように北海道の条丁目と同じ扱いにします。
公式サンプルが「place に入れるのは不適」と明示しているため推奨しません。

## B を実装する場合の要件

上の実測から確定した要件です。

- 数字は**全角算用と漢数字の両方**を受ける。半角は母集団に存在しないが、入力側にはありうる
- `第` はオプション（3分の1が `第` なし）
- **先頭と末尾の両方**を扱う。末尾は宮古市の27件（`区界第１地割` `江繫第１０地割`）
- **部分文字列一致は使えない。** `地割` を含むだけで判定すると38件を誤爆する

誤爆する38件は岩手県以外に分布し、「地割」を含む通常の字名です。

```
富山県 30件  飛地割 / 宮地割 / 覚地割 / 引地割 / 金剛地割 / 二番地割 ...
福島県  4件  字下地割 / 字下谷地割
青森県  2件  字地割 / 字地割出戸
山形県  1件  字谷地割
岐阜県  1件  字鎌地割
```

## 測定方法

母集団の走査は [scripts/measure-chiwari-master.ts](../scripts/measure-chiwari-master.ts) です。
ローカルに構築した `japanese-addresses-v2` を読むだけで、ネットワークも NJA も使いません。
全国で数秒で終わります。

```bash
NJA_API_BASE=.data/japanese-addresses-v2/out/api/ja node scripts/measure-chiwari-master.ts
```

走査の対象は `ja.json` の索引が挙げる自治体ファイルに限ります。
`out/api/ja` 配下を再帰的に走ると都道府県の索引まで拾い、母数が狂います。
上の訂正はこれで起きたものです。

発生率と分類はローカルミラー（2026-08-24 のデータ）で測っています。
岩手県の住所1,994件を通すだけなので8秒で終わります。

公開 API（2024-12-25 のデータ）で測った初期の値とは差があります。
入力に地割を含む212件で比べると、17件（8%）で分類が変わりました。
過去の測定値と突き合わせるときはデータの版に注意が必要です。
